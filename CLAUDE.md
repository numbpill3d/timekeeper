# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**Omniscient Home** — an AI-powered home surveillance intelligence platform. Cameras feed a real-time CV pipeline (YOLOv8 + ByteTrack + OSNet ReID) that produces structured events stored in TimescaleDB. Users query their home in natural language ("Where are my keys?") and get NL answers via a RAG + text-to-SQL pipeline.

## Commands

### Full stack

```bash
cp .env.example .env        # fill in secrets
docker compose up --build   # start everything
docker compose down -v      # tear down incl. volumes
```

### Individual services (local dev, requires infra running)

```bash
# from service dir, e.g. services/query-engine
PYTHONPATH=/home/.../timekeeper/shared pip install -r requirements.txt
uvicorn src.main:app --reload --port 8001
```

### Web frontend

```bash
cd apps/web
npm install

npm run build    # tsc + vite build
```

### Mobile (Expo)

```bash
cd apps/mobile
npm install
npx expo start           # QR for Expo Go
npx expo start --android
eas build --platform android
```

### DB migrations

The base schema lives in `infra/db/init.sql`; incremental upgrades live in
`infra/db/migrations/` and are applied by the Compose `db-migrate` sidecar.
For a manual run, apply the numbered migrations after the base schema against
a running TimescaleDB:

```bash
docker compose exec -T timescaledb psql -U omniscient -d omniscient \
  -f /docker-entrypoint-initdb.d/init.sql
for migration in infra/db/migrations/*.sql; do
  docker compose exec -T timescaledb psql -U omniscient -d omniscient \
    -f - < "$migration"
done
```

## Architecture

### Service topology

```
cameras → ingestion (direct streams or provider WebRTC adapters) → Kafka: omniscient.frames
                                      ↓
                              vision (YOLOv8+ByteTrack+ReID)
                                      ↓ omniscient.detections
                              event-processor (aggregator)
                                      ↓ omniscient.events
                  ┌───────────────────┴───────────────────┐
             alert-engine                             query-engine
             (Kafka consumer, Twilio/FCM)      (:8001, RAG+SQL+Ollama)
                                                         ↑
                                                   api (:8000, FastAPI)
                                                         ↑
                                              web (:3000) / mobile (Expo)
```

### Shared models package

`shared/omniscient_shared/` is a pip-installable package with Pydantic models and Kafka topic constants used by all Python services. In Docker it's bind-mounted as `/shared` and each service sets `ENV PYTHONPATH="/shared:$PYTHONPATH"`. Never pip-install it into images; the mount is the source of truth in dev.

### Kafka topics (`shared/omniscient_shared/kafka/topics.py`)

`omniscient.frames` → `omniscient.detections` → `omniscient.events` → `omniscient.alerts`

`FrameMessage` carries a **filesystem path** (`frame_path`), not base64 bytes, to stay under Kafka message size limits. Ingestion writes JPEGs to `/tmp/frames`; vision reads from there.

### Vision pipeline (`services/vision/src/pipeline.py`)

Per-camera `_trackers: dict[str, Tracker]` — ByteTrack is stateful and must be kept alive per stream. Detection uses YOLOv8; ReID uses OSNet via `torchreid` (optional, graceful fallback if unavailable). ReID gallery match threshold: cosine similarity ≥ 0.7.

For each frame, known-person ReID candidates are matched to object boxes using
the explainable spatial association in `services/vision/src/association.py`.
Object events carry the matched `person_id`, association method, and confidence
through the event processor, so queries can answer who handled an item without
inventing an identity when the boxes do not support it.

### Camera provider adapters (`services/ingestion/src/providers.py`)

Direct RTSP/HTTP(S)/HLS/file feeds use PyAV. Ring uses its authenticated WHEP
WebRTC session; Nest uses the Google Device Access `GenerateWebRtcStream`
command. Arlo and Wyze use a configured local RTSP or WHEP bridge because a
portable official cloud live-stream API is not assumed. Provider tokens remain
environment-only and non-secret endpoint/device settings live in
`cameras.provider_config`.

### Event aggregation (`services/event-processor/src/aggregator.py`)

`CameraAggregator` per camera maintains track_id state. First detection of a track_id → `person_entered`; no detection for `EXIT_TIMEOUT=5s` → `person_exited`. Embeddings for RAG are generated by calling the query-engine's `/embed` endpoint.

### Query engine pipeline (`services/query-engine/src/router.py`)

1. RAG: embed question → pgvector `<=>` cosine search over `events.embedding` (VECTOR(384), `all-MiniLM-L6-v2`), top-8 events as context
2. LLM: Ollama (`mistral`, temperature 0.0) → text-to-SQL; OpenAI fallback if `OPENAI_API_KEY` set
3. Safety: `_safe_sql()` rejects non-SELECT via regex; `_inject_owner_scope()` appends `camera_id IN (SELECT id FROM cameras WHERE owner_id = '...')` to prevent cross-user leakage
4. Synthesize: second LLM call converts rows → NL answer; if the LLM is unavailable, the evidence formatter produces a timestamped answer from recorded rows

### Auth (`api/src/auth.py`)

JWT (PyJWT + bcrypt). `CurrentUser = Annotated[dict, Depends(get_current_user)]`.
The API enforces the free query quota and camera limits from the user's stored
subscription tier: free=2 cameras and 10 queries/month, home=5, family=10,
pro=9999 cameras.

### WebSocket live events

`/ws/events` — the browser/mobile client sends the JWT in the
`timekeeper-auth` WebSocket subprotocol rather than the URL; an
`AIOKafkaConsumer` is created per connection with `auto_offset_reset="latest"`,
and events are filtered to the requesting user's `owner_id`.

## Database schema (`infra/db/init.sql`)

Key tables: `users`, `cameras`, `persons` (VECTOR(512) ReID + VECTOR(512)
FaceNet), `tracked_objects`, `detections` (TimescaleDB hypertable), `events`
(hypertable + VECTOR(384) embedding), `alert_rules`, and
`alert_deliveries`. IVFFlat indexes cover the vector columns.

## Web app (`apps/web/`)

React 18 + Vite + TanStack Query + Axios. Theme: `--accent: #cc0000`,
`--bg: #000000`, Terminus font. Vite proxies `/api/*` →
`http://localhost:8000`. Pages: Dashboard (activity feed + ChatPanel),
Timeline (event table), Cameras (CRUD), Persons, Alerts, and Settings.

## Mobile app (`apps/mobile/`)

Expo React Native. Bottom tabs: Home (activity summary), Chat (NL query),
Timeline, and Cameras. ChatScreen is the primary NL interface — sends to the
authenticated `/query` API route and shows a confidence badge if < 0.8.
